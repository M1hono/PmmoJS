# PMMO Settings Event

`PmmoJS.settings` is the main bridge for registering PMMO object data from `server_scripts/`.

## Single-target builders

These create one builder at a time:

- `event.item(itemOrId)`
- `event.block(blockOrId)`
- `event.entity(entityTypeOrId)`
- `event.biome(id)`
- `event.dimension(id)`
- `event.generic(objectType, objectOrId)`

For `item`, `block`, and `entity`, you can pass either the registered object or the registry id string directly.

```js
PmmoJS.settings(event => {
  event
    .item('minecraft:diamond_sword')
    .override(true)
    .setRequirement(ReqType.WEAPON, 'combat', 10)
    .setXp(EventType.CRAFT, 'smithing', 100)

  event
    .block('minecraft:diamond_ore')
    .override(true)
    .setRequirement(ReqType.BREAK, 'mining', 30)
    .setXp(EventType.BLOCK_BREAK, 'mining', 200)

  event
    .entity('minecraft:zombie')
    .override(true)
    .setXp(EventType.DEATH, 'combat', 25)
})
```

## Batch apply helpers

These apply the same builder callback to multiple targets:

- `event.items(targets, callback)`
- `event.blocks(targets, callback)`
- `event.entities(targets, callback)`
- `event.biomes(targets, callback)`
- `event.dimensions(targets, callback)`
- `event.genericMany(objectType, targets, callback)`

`targets` can be:

- one id
- one registered object
- a JS array
- a Java list or other iterable

This is the preferred path when you want to patch many objects with the same PMMO rule.

```js
PmmoJS.settings(event => {
  event.items([
    'minecraft:diamond_sword',
    'minecraft:netherite_sword',
    'minecraft:trident'
  ], setting => {
    setting.override(true)
    setting.setRequirement(ReqType.WEAPON, 'combat', 20)
    setting.setXp(EventType.CRAFT, 'smithing', 150)
  })

  event.entities([
    'minecraft:villager',
    'minecraft:wandering_trader'
  ], setting => {
    setting.override(true)
    setting.setRequirement(ReqType.ENTITY_INTERACT, 'charisma', 8)
  })
})
```

## Common builder methods

All settings builders inherit these methods:

- `setRequirement(reqType, skill, level)`
- `requirement(reqType, map)`
- `setXp(eventType, skill, amount)`
- `xp(eventType, map)`
- `override(boolean)`

## Type-specific features

Depending on the builder type you also get access to:

- item salvage configuration
- item and entity damage-type XP registration
- positive and negative mob-effect registration
- location mob modifiers
- vein-miner charge configuration
- NBT requirement, NBT XP, and NBT bonus builders

Example:

```js
PmmoJS.settings(event => {
  event
    .item('minecraft:diamond_pickaxe')
    .override(true)
    .veinChargeCap(128)
    .veinChargeRate(1.25)
    .veinConsumeAmount(2)
})
```

## Clearing default data

If you want a script-free wipe for broad PMMO categories, start with `config/pmmojs-common.toml`:

- `disableDefaultSettings.all`
- `disableDefaultSettings.skills`
- `disableDefaultSettings.perks`
- `disableDefaultSettings.requirements`
- `disableDefaultSettings.xpAwards`
- `disableDefaultSettings.itemExtras`
- `disableDefaultSettings.blockVeinData`

The settings event also exposes these legacy helpers:

- `clearVanillaItemSettings()`
- `clearVanillaBlockSettings()`
- `clearVanillaEntitySettings()`

Treat these as requirement-reset helpers, not as a full PMMO wipe API.

They are limited to broad requirement overrides. They are not a complete reset path for:

- XP awards
- bonuses
- positive or negative effects
- salvage
- vein data
- biome or dimension settings

For reset order, script patterns, and the location-data limits, use [Reset Defaults](./reset-recipes).

## Enum accuracy

Use real PMMO enum names from the current jar. For example:

- `ReqType.ENTITY_INTERACT` exists
- `ReqType.ENTITY` does not exist
- `EventType.BLOCK_BREAK` exists
- `EventType.BREAK` does not exist
- `EventType.DEATH` exists
- `EventType.KILL` does not exist
