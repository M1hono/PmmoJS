# Config Events

These hooks let you adjust PMMO config data from `server_scripts/`.

## Common Config: `config/pmmojs-common.toml`

Before KubeJS config events run, PmmoJS can suppress PMMO's built-in defaults through Forge common config.

Use this when you want your pack to start from a cleaner baseline without copying large reset scripts into `server_scripts/`.

```toml
[disableDefaultSettings]
all = false
skills = false
perks = false
requirements = false
xpAwards = false
itemExtras = false
blockVeinData = false
```

Order of operations:

1. PmmoJS reads `pmmojs-common.toml`
2. enabled reset categories clear PMMO defaults
3. `PmmoJS.skillsConfig`, `PmmoJS.perksConfig`, and `PmmoJS.settings` apply your custom data

That means the common config gives you an empty baseline, but your scripts still win afterward.

## `PmmoJS.skillsConfig`

Use this event to add, replace, or remove PMMO skills.

```js
PmmoJS.skillsConfig((event) => {
    event
        .addSkill("defense")
        .withColor(0x2f6fed)
        .withMaxLevel(100)
        .withIconSize(18)
        .build();

    event.removeDefaultSkill("swimming");
});
```

If you remove and re-add the same skill in one pass, the custom skill wins.

## `PmmoJS.globalsConfig`

Use this event to manage PMMO globals such as reusable NBT paths and constants.

```js
PmmoJS.globalsConfig((event) => {
    event.addPath("durability", "Damage");
    event.addConstant("MAX_SKILL_LEVEL", "100");
    event.removePath("old_path");
    event.removeConstant("OLD_CONSTANT");
});
```

## `PmmoJS.perksConfig`

Use this event to edit existing PMMO perk data.

```js
PmmoJS.perksConfig((event) => {
    event.clearPerks(EventType.SKILL_UP);
    event.removePerkType("pmmo:fireworks");
});
```

Core control methods:

- `addPerk(eventType, perkId, skill)`
- `clearPerks(eventType)`
- `removePerkType(perkId)`
- `removePerk(tag)`

Config merge behavior:

1. PmmoJS starts from PMMO's current `PerksConfig.PERK_SETTINGS`
2. `clearPerks(eventType)` replaces that event's list with an empty list
3. `removePerkType(perkId)` removes every matching `perk` entry across all events
4. `removePerk(tag)` removes entries by `perk` plus `skill`
5. `addPerk(...)` appends new perk tags to the selected event list

Base config keys written by the builder:

| Method | Written Key |
| --- | --- |
| `addPerk(eventType, perkId, skill)` | `perk`, `skill` |
| `withCooldown(...)` | `cooldown` |
| `withChance(...)` | `chance` |
| `withMinLevel(...)` | `min_level` |
| `withMaxLevel(...)` | `max_level` |
| `withPerXLevel(...)` | `per_x_level` |
| `withMilestones(...)` | `milestones` |
| `withString(...)`, `withBool(...)`, `withInt(...)`, `withLong(...)`, `withFloat(...)`, `withDouble(...)` | custom scalar keys |
| `withStringList(...)` | custom string-list keys |
| `withList(...)` | raw `ListTag` keys |
| `withCompound(...)` | nested compound keys |

Specialized builder families:

The table below describes the keys exposed by each builder. A key being exposed by PmmoJS does not guarantee that PMMO uses that key for every perk type.

| Builder | Extra Keys |
| --- | --- |
| `asAttributePerk()` | `attribute`, `multiplicative`, plus `max_boost`, `per_level`, `base` |
| `asTempAttributePerk()` | `attribute`, `multiplicative`, `duration`, plus `max_boost`, `per_level`, `base` |
| `asDamageBoostPerk()` | `applies_to`, `for_damage`, `multiplicative`, plus `max_boost`, `per_level`, `base` |
| `asDamageReducePerk()` | `for_damage`, plus `max_boost`, `per_level`, `base` |
| `asBreakSpeedPerk()` | `pickaxe_dig`, `axe_dig`, `shovel_dig`, `hoe_dig`, `shears_dig`, `sword_dig`, plus `max_boost`, `per_level`, `base` |
| `asEffectPerk()` | `effect`, `duration`, `modifier`, `ambient`, `visible`, `show_icon`, plus `max_boost`, `per_level`, `base` |
| `asCommandPerk()` | `command`, `function`, plus inherited base-key methods |
| `asFireworksPerk()` | `colors`, plus inherited base-key methods |
| `asJumpBoostPerk()` | `max_boost`, `per_level`, `base` |
| `asBreathPerk()` | `max_boost`, `per_level`, `base` |
| `asVillagerBoostPerk()` | `max_boost`, `per_level`, `base` |
| `asTameBoostPerk()` | `max_boost`, `per_level`, `base` |

Example:

```js
PmmoJS.perksConfig(event => {
  event
    .addPerk(EventType.SKILL_UP, 'pmmo:attribute', 'endurance')
    .asAttributePerk()
    .withAttribute(Java.loadClass('net.minecraft.world.entity.ai.attributes.Attributes').MAX_HEALTH)
    .withPerLevel(1)
    .withMaxBoost(10)
    .build()
})
```

## `PmmoJS.serverConfig`

Use this event for PMMO's server config values.

```js
PmmoJS.serverConfig((event) => {
    event
        .setMaxLevel(100)
        .setGlobalModifier(1.0)
        .setUseExponentialFormula(true)
        .setTreasureEnabled(true);

    event.addSkillModifier("defense", 1.1);
    event.addJumpXp("agility", 0.5);
    event.addPartyBonus("charisma", 0.1);
});
```

## `PmmoJS.autoValueConfig`

Use this event to override PMMO auto-value generation.

```js
PmmoJS.autoValueConfig((event) => {
    event
        .setAutoValuesEnabled(true)
        .setRaritiesModifier(1.5)
        .setHardnessModifier(2.0);

    event.addItemXpAward(EventType.CRAFT, "smithing", 25);
    event.addBlockReq(ReqType.BREAK, "mining", 5);
    event.setAxeOverride({
        woodcutting: 15,
    });
});
```

## `PmmoJS.antiCheeseConfig`

Use this event to edit AFK, diminishing-return, and normalization settings.

```js
PmmoJS.antiCheeseConfig((event) => {
    event.setAfkCanSubtract(false);

    event
        .addAfkSetting(EventType.BLOCK_BREAK)
        .minTime(600)
        .reduction(0.1)
        .cooloff(5)
        .tolerance(3.0)
        .strictTolerance(true)
        .build();
});
```

<Callout variant="info">
    These config hooks are applied from the server/static-data reload path so they
    stay compatible with PMMO config reloads and EMI tag synchronization.
</Callout>
