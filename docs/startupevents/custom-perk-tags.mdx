# Custom Perk Tags

Custom perks work with two tags: `ctx.getSettings()` and `ctx.getResult()`. Each tag has a different lifetime and merge path.

## The two tags in `start()`

`start()` is the only callback that has access to both tags.

### `ctx.getSettings()` — persistent state

Use this when a value needs to survive into later callbacks like `tick()` or `stop()`.

```js
.start(ctx => {
  ctx.getSettings().putBoolean('active', true)
  ctx.getSettings().putLong('started_at', ctx.getPlayer().level().getGameTime())
})
.tick(ctx => {
  if (ctx.getSettings().getBooleanOr('active', false)) {
    ctx.getPlayer().heal(1)
  }
})
```

`ctx.getSettings()` starts as a merged tag containing your startup defaults, `perks.toml` overrides, PMMO event input, and output from earlier perks. Whatever you write here persists through `tick()` and `stop()`. PMMO ignores keys it does not recognize, so you can store private lifecycle data freely.

### `ctx.getResult()` — one-shot output

Use this when the value is meant only for the current PMMO execution pass. PMMO merges the result tag back into the current execution so other perks in the same pass can read it.

```js
.start(ctx => {
  const incoming = ctx.getSettings().getDoubleOr('DAMAGE_IN', 0)
  if (incoming > 0) {
    ctx.getResult().putDouble('DAMAGE_OUT', incoming * 0.8)
  }
})
```

Typical uses: replacing damage values, adjusting break speed, or emitting event output that another perk in the same pass might consume.

## Common patterns

### A configurable field

Set a default in the builder, read it at runtime:

```js
PmmoJS.registerPerk(event => {
  event
    .create('kubejs:steady_mind', PMMOPerkSide.SERVER)
    .withInt('heal_interval', 20)
    .tick(ctx => {
      const interval = ctx.getSettings().getIntOr('heal_interval', 20)
      if (ctx.getElapsedTicks() % interval === 0) {
        ctx.getPlayer().heal(1)
      }
    })
    .register()
})
```

### State that must survive across callbacks

Write it to `ctx.getSettings()`:

```js
.start(ctx => {
  ctx.getSettings().putLong('started_at', ctx.getPlayer().level().getGameTime())
})
.stop(ctx => {
  const startedAt = ctx.getSettings().getLongOr('started_at', 0)
  // use the stored value
})
```

### Event output for PMMO

Write it to `ctx.getResult()`:

```js
.start(ctx => {
  const speed = ctx.getSettings().getFloatOr('BREAK_SPEED_INPUT_VALUE', 0)
  if (speed > 0) {
    ctx.getResult().putFloat('BREAK_SPEED_OUTPUT_VALUE', speed + 1.5)
  }
})
```

### A perk with only private fields

Custom keys are fine — PMMO ignores them:

```js
.defaults(tag => {
  tag.putString('mode', 'regen')
  tag.putDouble('amount', 1.0)
})
```

## Standard PMMO perk keys

These are the keys PMMO recognizes. You set them through builder methods, and PMMO reads them from the merged settings tag.

| Key | Type | Set by |
|---|---|---|
| `skill` | string | `withSkill(...)` |
| `level` | int | Injected by PMMO at runtime |
| `cooldown` | int | `withCooldown(...)` |
| `chance` | double | `withChance(...)` |
| `min_level` | int | `withMinLevel(...)` |
| `max_level` | int | `withMaxLevel(...)` |
| `per_x_level` | int | `withPerXLevel(...)` |
| `milestones` | int[] | `withMilestones(...)` |
| `duration` | int | `withDuration(...)` |

## PMMO event keys for perk I/O

When your perk processes PMMO events like damage or block breaking, you read input from `ctx.getSettings()` and write output to `ctx.getResult()`:

| Event type | Read from settings | Write to result |
|---|---|---|
| `BREAK_SPEED` | `BREAK_SPEED_INPUT_VALUE`, `BLOCK_POS` | `BREAK_SPEED_OUTPUT_VALUE` |
| `DEAL_DAMAGE`, `RECEIVE_DAMAGE` | `DAMAGE_IN` | `DAMAGE_OUT` |
| `JUMP`, `SPRINT_JUMP`, `CROUCH_JUMP` | — | `JUMP_OUT` |
| `SHIELD_BLOCK` | `DAMAGE_IN` | — |
| `ENCHANT` | `STACK`, `PLAYER_ID`, `ENCHANT_LEVEL`, `ENCHANT_NAME` | — |
| `SMELT` | `STACK` | — |

## Builder-to-key mapping

Every builder method writes a specific key into the startup default tag:

| Builder method | Key written |
|---|---|
| `withSkill(s)` | `skill` |
| `withCooldown(n)` | `cooldown` |
| `withDuration(n)` | `duration` |
| `withChance(n)` | `chance` |
| `withMinLevel(n)` | `min_level` |
| `withMaxLevel(n)` | `max_level` |
| `withPerXLevel(n)` | `per_x_level` |
| `withMilestones(arr)` | `milestones` |
| `withString(k, v)` | custom key (string) |
| `withBool(k, v)` | custom key (boolean) |
| `withInt(k, v)` | custom key (int) |
| `withLong(k, v)` | custom key (long) |
| `withFloat(k, v)` | custom key (float) |
| `withDouble(k, v)` | custom key (double) |
| `withStringList(k, arr)` | custom key (string list) |
| `withNumberList(k, arr)` | custom key (double list) |
| `withCompound(k, v)` | custom key (compound) |
| `defaults(tag => {})` | any combination through `PerkTagJS` |
