# PmmoJS 概览

`PmmoJS` 是一个面向 Forge `1.20.1` 的 Project MMO KubeJS 附属模组。

它为整合包作者提供三层控制能力：

1. 启动阶段注册自定义 PMMO 条件谓词与自定义 Perk 类型。
2. 通过服务端配置事件修改 `skills.toml`、auto-values、perks、globals 与 anti-cheese 等 PMMO 配置。
3. 通过运行时事件接入 XP、附魔、熔炉、回收、伤害惩罚、PMMO 的 `EventType` 触发器，以及 PMMO 处理器级内部钩子。

与 perk 编写直接相关的参考页：

- [标签模型](./tag-model)
- [自定义 Perk 标签](./startupevents/custom-perk-tags)
- [清空默认数据](./serverevents/reset-recipes)

如果你希望 PMMO 从更干净的基线开始运行，先改 `config/pmmojs-common.toml`，再通过 KubeJS 把整合包真正需要的数据加回去。

## 事件分组

启动事件：

- `PmmoJS.registerPredicate`
- `PmmoJS.registerPerk`

服务端配置事件：

- `PmmoJS.settings`
- `PmmoJS.globalsConfig`
- `PmmoJS.skillsConfig`
- `PmmoJS.perksConfig`
- `PmmoJS.serverConfig`
- `PmmoJS.autoValueConfig`
- `PmmoJS.antiCheeseConfig`

运行时事件：

- `PmmoJS.trigger`
- `PmmoJS.internal`
- `PmmoJS.xp`
- `PmmoJS.enchant`
- `PmmoJS.furnace`
- `PmmoJS.salvage`
- `PmmoJS.itemstackDamagePenalty`
- `PmmoJS.entityDamagePenalty`

## 绑定对象

插件会向脚本环境注册这些常用绑定：

- `EventType`
- `PMMOInternalType`
- `PMMOPerkSide`
- `ModifierDataType`
- `ObjectType`
- `ReqType`
- `PmmoHelper`

按脚本类型区分：

- `startup_scripts/`: `PmmoHelper`、`TagBuilder`、`NbtPathBuilder`
- `server_scripts/`: `PmmoHelper`、`SkillHelper`、`SKillHelper`、`CustomReqMap`、`TagBuilder`、`NbtPathBuilder`、`SalvageBuilder`
- `client_scripts/`: 只读的 `SkillHelper`、`SKillHelper`

`PmmoHelper` 是专门为 KubeJS 整理过的 PMMO 辅助入口，尽量避免重载导致的脚本歧义。它封装了这些高频能力：

- 读取与修改技能等级、技能 XP
- 查询需求、经验奖励与合并后的加成
- 直接注册 PMMO 数据
- 队伍与矿脉连锁相关逻辑
- 手动发放 XP、触发回收
- 通过 `getTriggerTypeIds()` 与 `getInternalTypeIds()` 枚举当前桥接能力
- 需要时直接注册 PMMO trigger listener，而不是只通过 `PmmoJS.trigger`

`PmmoJS.trigger(EventType.BREW, ...)` 现在在 `1.20.1` 上已经可用，而那些不会走 trigger registry 的 PMMO 处理器则统一通过 `PmmoJS.internal(...)` 暴露。

## 版本说明

- 目标 Minecraft 版本：`1.20.1`
- 目标 PMMO 版本线：`1.7.40`
- 开发环境中保留了 EMI 运行时依赖，用于复现配方查看器与标签重载相关问题

<Callout>
    使用 `startup_scripts/` 处理 predicate、perk 类型、直接 PMMO 数据注册，
    以及 `ForgeEvents.onEvent(...)`。使用 `server_scripts/` 处理 PMMO 配置、
    运行期事件，以及 `ProbeJSEvents.generateDoc(...)`。
</Callout>
