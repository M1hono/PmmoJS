# 运行时事件

这些事件会在游戏进行过程中触发，应写在 `server_scripts/` 中。

## `PmmoJS.trigger`

这个事件桥接了 PMMO 内部的 `EventTriggerRegistry`。只要 Project MMO 某个处理器实际执行了对应 `EventType` 的 trigger listener，KubeJS 就能通过这里接到回调。

它的意义是：不再需要为每个 PMMO 处理器单独做一层 KubeJS 包装，你可以统一通过 `PmmoJS.trigger` 监听 `BLOCK_BREAK`、`CRAFT`、`BLOCK_PLACE`、`DEAL_DAMAGE`、`RECEIVE_DAMAGE`、`FISH`、`TAMING`、`SHIELD_BLOCK` 等 PMMO 触发类型。

在 PMMO `1.20.1-1.7.40` 中，当前会经过这层桥接的触发类型包括：

- `ANVIL_REPAIR`、`BLOCK_BREAK`、`BREAK_SPEED`、`BLOCK_PLACE`、`BREED`、`BREW`、`CONSUME`、`CRAFT`
- `DEAL_DAMAGE`、`RECEIVE_DAMAGE`、`DEATH`、`ENCHANT`、`ENTITY`、`FISH`、`GROW`
- `HIT_BLOCK`、`ACTIVATE_BLOCK`、`ACTIVATE_ITEM`
- `JUMP`、`SPRINT_JUMP`、`CROUCH_JUMP`
- `GIVEN_AS_TRADE`、`RECEIVED_AS_TRADE`、`TAMING`、`SHIELD_BLOCK`
- `BREATH_CHANGE`、`HEALTH_CHANGE`、`HEALTH_INCREASE`、`HEALTH_DECREASE`
- `RIDING`、`EFFECT`、`SPRINTING`、`CROUCH`、`SUBMERGED`、`SWIMMING`、`DIVING`、`SURFACING`、`SWIM_SPRINTING`

这并不代表 PMMO 的每条运行时逻辑都属于 trigger registry。像维度切换、登录、坐骑、活塞、玩家死亡、爆炸、睡眠等处理器并不是 `EventType` trigger 路径，它们现在通过 `PmmoJS.internal` 单独暴露。

```js
PmmoJS.trigger(EventType.BLOCK_BREAK, event => {
    const player = event.getPlayer()

    if (player && player.stages.has('peaceful_mining')) {
        event.addXpAward('mining', 25)
    }

    if (player && player.isCreative()) {
        event.setCancelled(true)
    }
})
```

`PMMOTriggerEventJS` 上常用的方法：

- `getType()`、`getTypeId()`
- `getForgeEvent()`、`getForgeEventClassName()`
- `hasPlayer()`、`getPlayer()`、`getServerPlayer()`
- `getContext()` 以及 `getContextBoolean`、`getContextString`、`putContextInt`、`putContextCompound`
- `getXpAwards()`、`setXpAwards()`、`setXpAward()`、`addXpAward()`
- `setCancelled(true)`，它会把 PMMO 内部使用的 `is_cancelled` 标记写回上下文

<Callout variant="info">
    `PmmoJS.trigger` 适合处理 PMMO 的 `EventType` 运行时逻辑。
    如果你要控制的是没有经过 trigger registry 的 PMMO 处理器，请使用
    [`PmmoJS.internal`](./internal.mdx)。
</Callout>

## `PmmoJS.xp`

当 PMMO 为玩家某个技能增减 XP 时触发。

```js
PmmoJS.xp(event => {
    const player = event.getEntity()
    const skill = event.getSkill()

    if (event.isLevelUp() && event.endLevel() % 10 === 0) {
        player.give(Item.of('minecraft:diamond'))
    }

    if (skill === 'mining') {
        event.cancel()
    }
})
```

## `PmmoJS.enchant`

玩家进行附魔时触发。

```js
PmmoJS.enchant(event => {
    const ench = event.getEnchantmentInstance()
    SkillHelper.addXP(event.getEntity(), 'magic', 10 * ench.level)
})
```

## `PmmoJS.furnace`

PMMO 熔炉相关逻辑触发时执行。

```js
PmmoJS.furnace(event => {
    const input = event.getInput()
    if (input.id === 'minecraft:iron_ore') {
        // 自定义逻辑
    }
})
```

## `PmmoJS.salvage`

玩家执行 PMMO 回收时触发。

```js
PmmoJS.salvage(event => {
    const builder = event.getBuilder()
    builder.setSalvageMax(2)
    event.setOutputStack(Item.of('minecraft:iron_nugget', 2))
})
```

## 伤害惩罚事件

- `PmmoJS.itemstackDamagePenalty`
- `PmmoJS.entityDamagePenalty`

它们用于修改 PMMO 的需求未达标伤害惩罚，而不只是单纯取消原逻辑。

```js
PmmoJS.itemstackDamagePenalty(event => {
    event.setDamage(event.getDamage() * 0.75)
})

PmmoJS.entityDamagePenalty(event => {
    event.setDamage(event.getDamage() * 0.5)
})
```

## `PmmoHelper`

`PmmoHelper` 是推荐直接使用的 PMMO 辅助绑定，目的是绕开 KubeJS 对 Java 重载处理较弱的问题。

```js
ServerEvents.loaded(event => {
    const player = event.server.getPlayerList().getPlayers()[0]
    if (!player) return

    console.log(PmmoHelper.getSkillLevel(player, 'mining'))
    console.log(PmmoHelper.getItemRequirements(player.mainHandItem, ReqType.WEAR))
    console.log(PmmoHelper.getCurrentVeinCharge(player))
})
```

常用方法分组：

- 技能状态：`getSkillLevel`、`setSkillLevel`、`addSkillXp`、`getAllSkillLevels`
- 数据查询：`getItemXpAwards`、`getBlockRequirements`、`getConsolidatedModifiers`
- 直接注册：`registerRequirementData`、`registerXpAwardData`、`registerBonusData`、tooltip 注册、predicate 注册
- 发现辅助：`getTriggerTypeIds`、`getInternalTypeIds`
- PMMO 系统：`awardXpToPlayer`、`awardXpToPartyInRange`、`getPartyMembers`、`applyVeinMining`、`triggerSalvage`

<Callout variant="info">
    `PmmoHelper` 是面向 PMMO 全部常用逻辑的总入口。`SkillHelper` 仍然保留，
    适合旧脚本或只关心技能等级与 XP 的场景。`client_scripts/` 中不提供
    `PmmoHelper`。
</Callout>
