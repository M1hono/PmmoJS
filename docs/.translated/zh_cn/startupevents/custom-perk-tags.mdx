# 自定义 Perk Tag

当你编写自定义 Perk 时，你会用到两个 tag：`ctx.getSettings()` 和 `ctx.getResult()`。这一页解释每个 tag 的用途，以及什么时候用哪个。

要了解 tag 系统的全貌（包括触发器上下文 tag 和内部钩子上下文 tag），参见 [Tag 模型](../tag-model)。

## `start()` 中的两个 tag

`start()` 是唯一一个能同时访问两个 tag 的回调。

### `ctx.getSettings()` —— 持久状态

当某个值需要留存到后续回调（如 `tick()` 或 `stop()`）时使用。

```js
.start(ctx => {
  ctx.getSettings().putBoolean('active', true)
  ctx.getSettings().putLong('started_at', ctx.getPlayer().level().getGameTime())
})
.tick(ctx => {
  if (ctx.getSettings().getBooleanOr('active', false)) {
    ctx.getPlayer().heal(1)
  }
})
```

`ctx.getSettings()` 初始是一个合并后的 tag，包含你的启动默认值、`perks.toml` 覆盖、PMMO 事件输入以及更早 Perk 的输出。你写入的任何内容都会在 `tick()` 和 `stop()` 中持续存在。PMMO 会忽略它不认识的键，所以你可以自由存储私有生命周期状态。

### `ctx.getResult()` —— 一次性输出

当值只在当前 PMMO 执行趟次中有意义时使用。PMMO 将结果 tag 合并回当前执行中，供同一趟次中的其他 Perk 读取。

```js
.start(ctx => {
  const incoming = ctx.getSettings().getDoubleOr('DAMAGE_IN', 0)
  if (incoming > 0) {
    ctx.getResult().putDouble('DAMAGE_OUT', incoming * 0.8)
  }
})
```

典型用途：替换伤害值、调整挖掘速度，或者发出可能被同一趟次中另一个 Perk 消费的事件输出。

## 常见模式

### 可配置字段

在构建器中设置默认值，在运行时读取：

```js
PmmoJS.registerPerk(event => {
  event
    .create('kubejs:steady_mind', PMMOPerkSide.SERVER)
    .withInt('heal_interval', 20)
    .tick(ctx => {
      const interval = ctx.getSettings().getIntOr('heal_interval', 20)
      if (ctx.getElapsedTicks() % interval === 0) {
        ctx.getPlayer().heal(1)
      }
    })
    .register()
})
```

### 需要跨回调持久化的状态

写入 `ctx.getSettings()`：

```js
.start(ctx => {
  ctx.getSettings().putLong('started_at', ctx.getPlayer().level().getGameTime())
})
.stop(ctx => {
  const startedAt = ctx.getSettings().getLongOr('started_at', 0)
  // 使用存储的值
})
```

### 供 PMMO 使用的事件输出

写入 `ctx.getResult()`：

```js
.start(ctx => {
  const speed = ctx.getSettings().getFloatOr('BREAK_SPEED_INPUT_VALUE', 0)
  if (speed > 0) {
    ctx.getResult().putFloat('BREAK_SPEED_OUTPUT_VALUE', speed + 1.5)
  }
})
```

### 只有私有字段的 Perk

自定义键完全没问题 —— PMMO 会忽略它们：

```js
.defaults(tag => {
  tag.putString('mode', 'regen')
  tag.putDouble('amount', 1.0)
})
```

## PMMO 标准 Perk 键

以下是 PMMO 识别的一些键。你通过构建器方法设置它们，PMMO 从合并后的设置 tag 中读取。

| 键 | 类型 | 设置方式 |
|---|---|---|
| `skill` | string | `withSkill(...)` |
| `level` | int | 由 PMMO 在运行时注入 |
| `cooldown` | int | `withCooldown(...)` |
| `chance` | double | `withChance(...)` |
| `min_level` | int | `withMinLevel(...)` |
| `max_level` | int | `withMaxLevel(...)` |
| `per_x_level` | int | `withPerXLevel(...)` |
| `milestones` | int[] | `withMilestones(...)` |
| `duration` | int | `withDuration(...)` |

## Perk I/O 的 PMMO 事件键

当你的 Perk 处理 PMMO 事件（如伤害或方块破坏）时，你从 `ctx.getSettings()` 读取输入，向 `ctx.getResult()` 写入输出：

| 事件类型 | 从 settings 读取 | 写入到 result |
|---|---|---|
| `BREAK_SPEED` | `BREAK_SPEED_INPUT_VALUE`、`BLOCK_POS` | `BREAK_SPEED_OUTPUT_VALUE` |
| `DEAL_DAMAGE`、`RECEIVE_DAMAGE` | `DAMAGE_IN` | `DAMAGE_OUT` |
| `JUMP`、`SPRINT_JUMP`、`CROUCH_JUMP` | — | `JUMP_OUT` |
| `SHIELD_BLOCK` | `DAMAGE_IN` | — |
| `ENCHANT` | `STACK`、`PLAYER_ID`、`ENCHANT_LEVEL`、`ENCHANT_NAME` | — |
| `SMELT` | `STACK` | — |

## 构建器方法到键的映射

每个构建器方法都会向启动默认 tag 写入一个特定的键：

| 构建器方法 | 写入的键 |
|---|---|
| `withSkill(s)` | `skill` |
| `withCooldown(n)` | `cooldown` |
| `withDuration(n)` | `duration` |
| `withChance(n)` | `chance` |
| `withMinLevel(n)` | `min_level` |
| `withMaxLevel(n)` | `max_level` |
| `withPerXLevel(n)` | `per_x_level` |
| `withMilestones(arr)` | `milestones` |
| `withString(k, v)` | 自定义键（string） |
| `withBool(k, v)` | 自定义键（boolean） |
| `withInt(k, v)` | 自定义键（int） |
| `withLong(k, v)` | 自定义键（long） |
| `withFloat(k, v)` | 自定义键（float） |
| `withDouble(k, v)` | 自定义键（double） |
| `withStringList(k, arr)` | 自定义键（string list） |
| `withNumberList(k, arr)` | 自定义键（double list） |
| `withCompound(k, v)` | 自定义键（compound） |
| `defaults(tag => {})` | 通过 `PerkTagJS` 设置任意组合 |
