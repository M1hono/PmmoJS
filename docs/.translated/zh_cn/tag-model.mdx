# Tag 模型

PmmoJS 在多个不同的地方使用 NBT tag。光看 Perk 系统，你就能在至少四种不同的场景中见到 tag。这一页解释每种 tag 是干什么的，以及什么时候该用哪一种。

## 一句话总结

PmmoJS 中的 tag 分为两大类：

- **静态 tag** 定义数据，在游戏会话之间持久存在。例如：Perk 启动默认值、Perk 配置条目。
- **运行时 tag** 承载单次执行路径的实时状态，执行路径结束后就消失。例如：触发器上下文、内部钩子上下文、Perk 执行设置。

最重要的规则：当 tag 需要供后续生命周期阶段（如 `tick()` 或 `stop()`）使用时，写入 `ctx.getSettings()`。当 tag 只在当前执行趟次中有意义时，写入 `ctx.getResult()`。

## Tag 出现的场景

| 系统 | API | Tag 类型 | 生存期 |
|---|---|---|---|
| 启动 Perk 注册 | `PmmoJS.registerPerk(...)` | `PerkTagJS`（封装 `CompoundTag`） | 静态 —— 成为 Perk 的默认设置 |
| Perk 执行回调 | `ctx.getSettings()`、`ctx.getResult()` | `PerkTagJS` | 运行时 —— 每次 Perk 执行时全新构建 |
| 触发器钩子 | `PmmoJS.trigger(...)` | 可变 `CompoundTag` 上下文 | 运行时 —— 一次触发器调度 |
| 内部钩子 | `PmmoJS.internal(...)` | 可变 `CompoundTag` 上下文 | 运行时 —— 一次内部处理器调度 |
| XP 事件 | `PmmoJS.xp(...)` | 原始 `CompoundTag` | 运行时 —— 一次 XP 事件 |
| Perk 配置编辑 | `PmmoJS.perksConfig(...)` | 静态 `CompoundTag` 条目 | 静态 —— 存储在 PMMO 的配置中 |
| 直接触发器监听器 | `PmmoHelper.registerTriggerListener(...)` | 原始 `CompoundTag` | 运行时 —— 一次监听器调用 |

## Perk tag 详解

当你用 `PmmoJS.registerPerk(...)` 注册 Perk 时，`withSkill(...)`、`withCooldown(...)`、`withInt(...)` 等构建器方法会把值写入**启动默认 tag**。这个 tag 定义了 Perk 的初始配置。

在运行时，PMMO 会为每次 Perk 执行构建一个**合并后的设置 tag**，按以下顺序组合数据来源：

1. 你在 `registerPerk` 中设置的启动默认值
2. `perks.toml` 中匹配的条目（如果有的话）
3. 当前 PMMO 事件传入的数据
4. 同一执行趟次中更早 Perk 的输出

如果合并后的 tag 中包含 `skill` 字段，PMMO 还会把玩家当前在该技能上的等级作为 `level` 字段注入。

这个合并后的 tag 就是你在 Perk 回调中通过 `ctx.getSettings()` 访问的内容。

### 各回调能做什么

| 回调 | 通常读取的内容 | 通常写入的内容 |
|---|---|---|
| `conditions(ctx)` | `ctx.getSettings()` | 返回 `true` 或 `false` |
| `start(ctx)` | `ctx.getSettings()` | 持久状态写入 `ctx.getSettings()`，一次性输出写入 `ctx.getResult()` |
| `tick(ctx)` | `ctx.getSettings()`、`ctx.getElapsedTicks()` | 通常写入 `ctx.getSettings()` 存放私有生命周期状态 |
| `stop(ctx)` | `ctx.getSettings()` | 清理逻辑写入 `ctx.getSettings()` |
| `status(ctx)` | `ctx.getSettings()` | 通过 `addLine(...)` 或 `addLines(...)` 输出 UI 文本行 |

只有 `start()` 能访问 `ctx.getResult()`。PMMO 会把你写入其中的内容合并回当前 Perk 执行中，供其他 Perk 读取。PMMO 会忽略 `tick()` 和 `stop()` 的返回值。

## PerkTagJS 参考

`PerkTagJS` 是启动 Perk 中使用的 tag 封装，提供带类型的 get/set 方法，无需直接操作原始 NBT。

### 读取值

- `keys()` —— 列出所有键
- `has(key)` —— 检查键是否存在
- `getString(key)`、`getStringOr(key, fallback)`
- `getInt(key)`、`getIntOr(key, fallback)`
- `getLong(key)`、`getLongOr(key, fallback)`
- `getFloat(key)`、`getFloatOr(key, fallback)`
- `getDouble(key)`、`getDoubleOr(key, fallback)`
- `getBoolean(key)`、`getBooleanOr(key, fallback)`
- `getOrCreateCompound(key)` —— 获取或创建嵌套的 compound

### 写入值

- `remove(key)` —— 删除键
- `clear()` —— 删除全部
- `putString(key, value)`
- `putBoolean(key, value)`
- `putInt(key, value)`
- `putLong(key, value)`
- `putFloat(key, value)`
- `putDouble(key, value)`
- `putCompound(key, value)`
- `putStringList(key, values)`
- `putNumberList(key, values)` —— 将值存储为 double
- `merge(value)` —— 将另一个 compound 的键合并到当前 compound

### PMMO 专用辅助方法

- `getSkill()` —— 此 Perk 关联的技能名称
- `getResolvedLevel()` —— 玩家当前在该技能上的等级
- `getCooldown()` —— Perk 的冷却时间（tick）
- `getDuration()` —— Perk 的持续时间（tick）
- `getChance()` —— Perk 的激活概率（0.0 到 1.0）

## 触发器上下文 tag

`PmmoJS.trigger(...)` 通过事件对象给你一个可变的 `CompoundTag`。生命周期很简单：

1. PMMO 准备一个触发器上下文 tag
2. 你的 KubeJS 脚本读取并修改这个 tag
3. 你的脚本返回后，修改后的 tag 回到 PMMO
4. PMMO 可以继续使用这个 tag，包括将其传入 Perk 执行

推荐使用事件对象的 `getContext*` / `putContext*` 辅助方法，而不是直接编辑原始 tag。

XP 奖励辅助方法同样可用：`getXpAwards()`、`setXpAwards(map)`、`setXpAward(skill, amount)`、`addXpAward(skill, amount)`、`clearXpAwards()`。

要取消 PMMO 对本次触发器的处理，调用 `event.setCancelled(true)`。

## 内部钩子上下文 tag

`PmmoJS.internal(...)` 的工作方式与触发器类似，但初始时只有一个新的空 `CompoundTag`。在脚本运行之前，桥接层可能会向该 tag 注入钩子专属的数据。

与触发器的主要区别：

- 内部钩子以空 tag 开始（触发器接收 PMMO 准备好的上下文）
- 内部钩子有行动控制方法：`event.skipPmmo()`（跳过 PMMO 的处理器）、`event.deny()`（取消 Forge 动作并跳过 PMMO）
- 部分钩子会收到桥接层注入的键：`EXPLOSION` 获得 `affectedBlockCount` 和 `affectedEntityCount`，`POTION_BREW` 获得 `alreadyTracked` 和 `markBrewed`

## 最佳实践

- 在 Perk 回调内使用 `PerkTagJS` 方法（如 `getIntOr`、`putBoolean`），而不是直接调用原始 NBT。
- 使用 `ctx.getSettings()` 存放后续回调需要的状态。
- 只在 `start()` 中使用 `ctx.getResult()` 存放应流入当前 PMMO 执行趟次的输出。
- 对于触发器和内部钩子的上下文，使用事件对象上的 `getContext*` / `putContext*` 辅助方法。
- 只有在 API 明确暴露原始 `CompoundTag` 时才直接使用它（例如 `PmmoJS.xp(...)` 或 `PmmoHelper.registerTriggerListener(...)`）。
